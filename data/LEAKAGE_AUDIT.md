## 1. Rows removed or flagged

| Step | Trials | Note |
|---|---|---|
| Finished trials in `trials.parquet` | 155288 | COMPLETED or TERMINATED, started 2010–2020 |
| − registered after primary completion | 25035 | 1.9% of these are terminated (vs about 12% overall) |
| **Kept** | **130253** | 20 trials have no end date at all, so they could not be checked and were kept |
| Flagged `covid_terminated` (kept, not dropped) | 1285 | 92 of them have a primary completion date before 2020 (checked by hand, see below) |

**Why late registrations are dropped:** registered after primary completion: the outcome was already known when the trial was first registered, so no prediction 'at trial start' was ever possible (and almost all of these are COMPLETED, which would teach a false shortcut).

**COVID flag:** label = TERMINATED and why_stopped matches the COVID keyword pattern (why_stopped is used only for this flag, never as a feature). Manual check of the flagged trials with a primary completion date before 2020: their why_stopped texts really do give COVID-19 or the pandemic as a reason (e.g. "suspended in March 2020 due to COVID"). For a terminated trial the registry often records the last participant's date as the end date, before the pause, so these are true COVID stops, not keyword false positives.

## 6. Excluded columns

| Column | Dictionary says | Why it is not a feature |
|---|---|---|
| `nct_id` | yes | Identifier, kept only to join rows. Carries no information about the outcome. |
| `brief_title` | yes | Free text. Could be used later with text embeddings; not in this simple feature set. |
| `overall_status` | label | The raw status the label comes from (the answer itself). |
| `label` | label | The target. |
| `start_date` | yes | Used only for the time-based split (via start_year). |
| `start_year` | yes | Used only for the time-based split. As a feature it can't describe future years the model has never seen. |
| `start_date_type` | caution | Describes the record's format, not the trial: 37% are empty only because the records are old. |
| `first_submit_date` | yes | Used only to drop late registrations. As a feature (registration delay) it leaks: trials registered after they ended are almost all COMPLETED. |
| `primary_completion_date` | no | Known only when the trial ends. Used only to drop late registrations. |
| `completion_date` | no | Known only when the trial ends. Used only as a fallback end date for the late-registration filter. |
| `last_update_date` | no | Known only after the trial: finished trials are updated when they close. |
| `why_stopped` | no | Filled almost only for TERMINATED trials, so it nearly is the label. Used only to flag COVID-terminated trials (data cleaning), never as a feature. |
| `has_results` | no | Results are posted after the trial ends. |
| `enrollment_count` | no | LEAKAGE (reclassified from caution in Phase 8): ~98% of finished trials hold the ACTUAL final number, and trials that stop early enroll fewer people (median 19 vs 60). It would also cause a train/serve mismatch: a live recruiting trial only has the PLANNED number, so the model would be trained on one meaning and used on another. |
| `enrollment_type` | no | ACTUAL or ESTIMATED: says whether the trial has finished, so it is leakage. |
| `phases` | yes | Duplicate of `phase` (same information as a list). |
| `intervention_mesh_terms` | yes | Thousands of distinct drug/device terms and 45% empty. The intervention types (DRUG, DEVICE, ...) are used instead. |
| `lead_sponsor_name` | yes | About 19,500 distinct names. It would need target encoding, which easily leaks; `lead_sponsor_class` is used instead. |
| `conditions` | yes | Free text as written by the sponsor (thousands of values). Grouped into MeSH disease areas instead. |
